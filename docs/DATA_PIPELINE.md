# PLC-LLM-OS Data Pipeline

This document details how raw synthetic data generated by the LLM Swarm is captured, processed, deduplicated, and packaged into the final PyTorch-ready dataset.

---

## 1. Directory Structure

The data pipeline relies on a strict directory separation between "raw" concurrent output and "compiled" master outputs.

```text
PLC-LLM-OS/
├── data/
│   ├── swarm_raw/               # INBOX: Isolated agent payloads (.json)
│   ├── master/                  # COMPILED: Final ML dataset files
│   │   ├── train.jsonl
│   │   ├── validation.jsonl
│   │   └── dataset_card.md
├── pipeline/
│   └── tools/
│       └── build_master_dataset.py  # The aggregation script
```

## 2. Raw Swarm Data (The Inbox)

During an active Swarm Pulse, agents write single JSON files to `data/swarm_raw/`. 

**Schema Structure:**
Every raw file contains a conversational array compatible with standard instruction-tuning formats (like OpenAI's or HuggingFace's Chat Templates).

```json
{
  "messages": [
    {
      "role": "user",
      "content": "You are part of the Lumina AI Cloud Swarm... Invent a highly complex control scenario for: Wind Turbine Nacelle..."
    },
    {
      "role": "assistant",
      "content": "```iec-st\nFUNCTION_BLOCK FB_WindNacelle\nVAR_INPUT\n...\n```"
    }
  ]
}
```

## 3. The Compilation Script (`build_master_dataset.py`)

When the user pauses the generation loop, the master build script is executed. 

**Execution Flow:**
1. **Sweep:** The script scans `data/swarm_raw/` for all `.json` files.
2. **Load & Validate:** It loads each JSON and validates that it contains a user prompt and an assistant response with a valid IEC ST code fence (```iec-st).
3. **Deduplication:** It checks the new payloads against previously compiled data to ensure no identical responses or identical prompts are appended twice.
4. **Append:** Valid, unique records are appended to `data/master/train.jsonl` (90%) and `data/master/validation.jsonl` (10%).
5. **Sweep Clean:** Successfully merged raw files are optionally archived or cleaned up to keep the inbox empty for the next swarm session.
6. **Card Update:** `data/master/dataset_card.md` is updated with the latest token and record counts.

## 4. Git Versioning

Because the dataset scales massively over time, the compiled `.jsonl` files (and potentially `.csv`/`.parquet` versions in the future) are versioned using Git. The orchestration agent is instructed to run `git commit` and `git push` upon every successful build pipeline execution to ensure data is safely backed up to the remote repository.
