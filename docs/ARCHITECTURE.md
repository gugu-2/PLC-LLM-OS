# PLC-LLM-OS Architecture Overview

The **PLC-LLM-OS** project is an ambitious initiative to build the world's most advanced fine-tuned Large Language Model for Industrial Automation and Control Systems (IACS). The model specializes in writing highly complex, deterministic IEC 61131-3 Structured Text (ST). 

To achieve this, the project leverages a continuous, automated "Swarm" of AI agents acting as domain experts to generate massive amounts of synthetic training data.

---

## 1. High-Level Architecture

The system is divided into three primary tiers:

1. **Generation Tier (The Swarm):** An orchestration of Antigravity AI Subagents (using Gemini 3.1 Pro / 3.7 Flash) that operate continuously in the background. They are dynamically assigned ultra-niche industrial domains (e.g., Cryogenic Energy Storage, Rotary Kiln Cement Plants) and generate deep, complex ST function blocks.
2. **Data Pipeline Tier:** A localized processing engine that sweeps the raw output generated by the swarm, deduplicates the code, formats it into conversational `messages` structures, and splits it into `train.jsonl` and `validation.jsonl` files.
3. **Model Fine-Tuning Tier (Future):** PyTorch-based training scripts (e.g., `train_plc_llm.py`) configured to pull the compiled master dataset, leverage an `HF_TOKEN`, and fine-tune a base model for ST fluency.

## 2. The Agent Swarm Workflow

The AI Swarm is orchestrated through an **Infinite Loop Cron Job**:
* **Trigger:** A background cron daemon fires every 6 minutes.
* **Dispatch:** The primary orchestrator agent receives a `CRITICAL: Swarm Pulse` ping.
* **Execution:** The orchestrator spawns exactly three `SyntheticDataEvolverV3` subagents. 
* **Model Tier:** The `pro` tier model is strictly used, as generating valid, safe, and highly deterministic IEC 61131-3 logic requires deep physics, engineering, and syntax reasoning capabilities.

## 3. Data Collision & Integrity Management

Because the swarm operates concurrently in the cloud, standard file I/O operations (like appending to a single JSONL file) are highly susceptible to race conditions and file lock corruption. 

**The UUID Isolation Strategy:**
To guarantee absolute data integrity, every subagent is strictly prompted to use Python to write its payload to an isolated file using `uuid4()`. 
```python
import json, uuid
# ... Payload generation ...
with open(f"data/swarm_raw/agent_{uuid.uuid4().hex[:8]}.json", "w") as f:
    json.dump(record, f)
```
These isolated files are aggregated only when the user halts the swarm and explicitly commands a pipeline sweep.

## 4. API & Resource Quota Management

A critical component of the architecture is managing cloud API quotas. Generating >1500 characters of dense logic using `pro` tier models consumes significant compute.
* The 6-minute cron interval (`*/6 * * * *`) is a hard requirement. It allows three concurrent agents to complete their tasks and spin down without hitting `429 Resource Exhausted` rate limits.

## 5. Security & Safety Guardrails

The swarm intentionally operates in advanced industrial contexts, crossing into critical infrastructure. 
* **Nuclear and Radiological Block:** The model's inherent safety filters will actively refuse to generate PLC logic for radioactive systems (e.g., Cobalt-60 Gamma Irradiation, Nuclear Weapons manufacturing). 
* **Domain Steering:** The orchestrator agent must dynamically steer domain assignments toward manufacturing, renewable energy, materials science, and food processing to avoid wasted pulses blocked by safety guardrails.
